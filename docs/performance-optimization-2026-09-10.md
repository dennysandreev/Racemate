# Оптимизация RaceSide — 10 сентября 2026

Изменения внедрены на https://raceside.online/. Глобус на главной, код сцены, геометрия, текстуры и взаимодействия не менялись. Существующие пользовательские изменения в рабочем каталоге сохранены; в релиз переданы только правки этой задачи.

## Что изменено

- **HTTP/2 и потоковая отдача HTML.** В отдельном virtual host RaceSide включён HTTP/2, отключена буферизация ответа upstream. Остальные сайты общего nginx не менялись. Сжатие gzip уже работало и сохранено.
- **Независимая загрузка.** Оболочка сайта больше не ждёт профиль, права администратора и следующую сессию. Главная получает новости, отчёт, таблицы и рынки отдельными блоками. Фильтры и дайджест не задерживают основное содержимое лент.
- **Обратная связь при переходах.** Навигация показывает состояние перехода; для тяжёлых списков используются skeleton-состояния после проверки сезона. Предзагрузка ссылок запускается по наведению или фокусу, с учётом экономии трафика и медленных соединений.
- **Кеш запросов.** Добавлены короткие TTL для публичных сезонов, команд, социальных публикаций и фильтров. Кеш профилей отделён от публичного лимита; популярные записи сохраняются по LRU. Персональная лента не попадает в общий кеш, авторизованный просмотр сезонов и команд обходит публичный кеш.
- **Более лёгкие новости.** Списки не выбирают полный текст, highlights и весь исходный payload. Старый механизм поиска изображения сохранён отдельной выборкой только для записей без готового URL. Там, где пагинация не нужна, отключён точный подсчёт общего количества. Полная статья продолжает получать полный текст.
- **Изображения.** Превью новостей получают размеры, соответствующие карточке. Схемы трасс календаря проходят через Next Image. Версия схемы зависит от содержимого файла; версия в URL позволяет годовой кеш с обновлением адреса при смене файла. Пути с параметрами разрешены только для изображений трасс, остальные локальные картинки сохраняют прежнее правило без query string.
- **Индексы PostgreSQL.** Применена миграция `20260909215644_public_feed_read_indexes.sql`: частичные индексы хронологического чтения опубликованных новостей и постов. Данные и политики доступа не изменялись.
- **Прогрев.** Активирован существующий сервис прогрева, список расширен до 10 адресов. Он ждёт здоровый web-контейнер и обновляет публичный кеш каждые 30 секунд. Фоновые обработчики продолжают работать на прежнем образе.

Это локальные изменения в существующем стеке, без новых зависимостей и замены архитектуры.

## Замеры

Изолированные контексты Chromium, пустой браузерный кеш. Компьютер: 1440×1000. Мобильный сценарий: 390×844, DPR 2, 1,6 Мбит/с, задержка 150 мс, CPU ×4. После релиза серверный кеш прогрет. Исходные и итоговые значения — в [JSON](performance-2026-09-10.json).

Контрольный EXPLAIN ANALYZE: запрос соцсетей перестал сортировать около тысячи записей и читает нужные 13 через индекс; замер 106,6 → 4,0 мс. Новости: 9,9 → 0,5 мс, чтение нужных 21 записи через индекс. Это отдельные измерения, не гарантированный множитель ускорения всех запросов.

## Проверки

- `pnpm lint`, `pnpm typecheck`, production build локально и в Linux Docker — успешно.
- 44 теста: кеш и его изоляция, архивные сезоны/RLS, сезонная навигация, пакетные запросы, границы админского доступа, защищённая выдача социальных медиа, данные и геометрия глобуса.
- Браузер: главная, новости, календарь, чемпионат, команды, соцсети, текущий этап; нет ошибок JavaScript и сломанных изображений. Мобильный календарь без горизонтального переполнения. Предзагрузка по наведению подтверждена.
- Неверные сезоны и несуществующая новость возвращают HTTP 404. Проверено локально, в отдельном контейнере и на домене.
- HTTP/2, заголовки кеша и обработка схем трасс подтверждены на домене. Web-контейнер здоров, прогрев: `pages=10 failed=0`.
- Production `.env*` проверены по SHA-256: содержимое не менялось.

В ходе проверки ранние route-level loading-состояния заменены локальными границами после валидации, чтобы сохранить HTTP 404. Для социальных публикаций внешняя граница loading убрана: она провоцировала раннюю загрузку лишних фотографий. Контрольный замер на домене после исправления — 3,1 секунды; индикатор перехода и отдельная загрузка фильтров сохранены.

## Развёртывание и ограничения

- Активный сайт: `/home/racemate/app`.
- Релиз с исходниками: `/home/racemate/releases/20260910-performance`.
- Резервная копия исходников, Compose, nginx и старого image id: `/home/racemate/backups/20260910-performance`.
- Текущий web/cache-warmer image: `raceside:performance-20260910-v2`.
- Образ до изменений сохранён как `raceside:before-performance-20260910`.
- Актуальная Compose-конфигурация без секретов сохранена в `deploy/docker-compose.server.yml`; nginx — в `deploy/nginx.raceside.conf`.

Публичные данные могут отставать на время TTL; при обновлении кеша допустима кратковременная выдача предыдущего результата. Приватные страницы не кешируются целиком. Сессии авторизованного пользователя вручную не проверялись; проверки границ доступа прошли.

На мобильной главной значимого ускорения LCP нет. Сценарий с глобусом сохранён по условию задачи. Лабораторные замеры не заменяют статистику реальных пользователей; величина эффекта зависит от устройства, сети, состояния серверного кеша и текущего контента. Resource Timing может не учитывать размер картинок за междоменным редиректом, поэтому трафик соцсетей не использован как основной показатель.

На диске сервера остаётся около 2,7 ГБ. Посторонние образы, бэкапы и данные не удалялись. Обновление собрано с уже установленными зависимостями, чтобы ограничить расход места.
