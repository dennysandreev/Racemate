# SEO-план RaceSide

Дата технического аудита: 22 июля 2026 года.

## Цель

Сделать публичные страницы RaceSide понятными для поисковых систем, убрать из индекса служебные и дублирующиеся URL и выстроить устойчивый рост органического трафика по русскоязычным запросам о Формуле-1.

## Что уже сделано в коде

- Единый шаблон метаданных: уникальные `title`, `description`, canonical, Open Graph, Twitter Cards и правила индексации.
- Динамические метаданные для новостей, этапов календаря, пилотов, команд, чемпионата и исторических сезонов.
- JSON-LD для сайта и организации, новостей, хлебных крошек, спортивных событий, пилотов, команд и списков.
- Динамический sitemap с опубликованными новостями, сезонами, гонками, пилотами, командами и таблицами чемпионата.
- Обновлённый `robots.txt` без блокировки страниц, на которых поисковику нужно увидеть `noindex`.
- `X-Robots-Tag` для аккаунта, авторизации, админки, API, онбординга, прогнозов и коротких ссылок.
- Canonical/noindex-правила для фильтров, пагинации и служебных query-параметров.
- Человекочитаемые URL новостей из редакционных заголовков с постоянными редиректами со старых UUID-адресов.
- Осмысленные `alt` у контентных изображений новостей.
- Служебные и незаполненные разделы исключены из индекса до появления полноценного содержания.

## План действий

### P0 — сразу после публикации, 1–3 дня

1. Опубликовать изменения и очистить CDN-кэш.
2. Проверить в production:
   - ответы `200` у ключевых страниц;
   - canonical, robots и JSON-LD в исходном HTML;
   - `/robots.txt` и `/sitemap.xml`;
   - отсутствие служебных URL в sitemap;
   - корректную отдачу изображений и социальных превью.
3. Добавить сайт в Google Search Console и Яндекс Вебмастер, если этого ещё нет.
4. Подтвердить домен и отправить `https://raceside.online/sitemap.xml` в обе системы.
5. Запросить переобход главной, новостей, календаря, чемпионата и 3–5 свежих материалов.
6. Проверить по одному URL каждого типа в Google Rich Results Test и Schema.org Validator.
7. Зафиксировать стартовые показатели в одном отчёте:
   - индексируемые и исключённые страницы;
   - показы, клики, CTR и средняя позиция;
   - брендовые и небрендовые запросы;
   - LCP, INP и CLS на мобильных и десктопах;
   - страницы с ошибками 4xx/5xx.

Критерий готовности: sitemap принят, ключевые URL доступны для сканирования, критических ошибок разметки нет, служебные маршруты не индексируются.

### P1 — первые 2 недели

1. Собрать семантическое ядро по кластерам:
   - новости Формулы-1;
   - календарь и расписание Гран-при;
   - результаты гонок и положение в чемпионате;
   - пилоты и команды;
   - отдельные этапы и трассы;
   - исторические сезоны.
2. Сопоставить каждому кластеру одну целевую страницу, чтобы страницы не конкурировали между собой.
3. Переписать описания ключевых разделов под реальный поисковый спрос, сохранив живой продуктовый язык.
4. Добавить контекстные внутренние ссылки:
   - из новости на пилота, команду и этап;
   - из этапа на новости, результаты и положение в чемпионате;
   - из профиля пилота на команду и связанные материалы;
   - из исторического сезона на гонки и итоговые таблицы.
5. Ввести редакционный шаблон материала: автор или редакция, дата публикации и обновления, первоисточник, связанные сущности и минимум одна внутренняя ссылка.
6. Проверить источники изображений. Невалидные URL и ответы с неверным `Content-Type` заменять до публикации, чтобы карточки не оставались без изображения.
7. Подготовить отдельные социальные изображения для главной, календаря, чемпионата и наиболее важных материалов.

Критерий готовности: у каждого приоритетного запроса есть одна релевантная посадочная страница, а ключевые сущности связаны внутренними ссылками.

### P2 — 3–6 недель

1. Наполнить самостоятельным содержанием и открыть для индексации будущие разделы:
   - `/drivers` — каталог пилотов;
   - `/tracks` — каталог трасс;
   - `/seasons` — навигация по архиву;
   - `/reports` — авторские разборы.
2. Для каждого Гран-при создать устойчивую посадочную страницу с расписанием, трассой, результатами, связанными новостями и итогами уикенда.
3. Для пилотов и команд добавить уникальные вводные тексты и полезную статистику, а не повторяющиеся шаблонные абзацы.
4. Создать вечнозелёные материалы: правила Формулы-1, форматы сессий, система очков, регламент сезона и гид по командам.
5. Добавить видимую дату обновления там, где содержание меняется после гонки или по ходу сезона.
6. Провести Web Vitals-аудит шаблонов с наибольшим органическим потенциалом: новость, список новостей, этап, пилот и команда.

Критерий готовности: новые разделы имеют самостоятельную ценность, уникальный интент и попадают в sitemap только после полноценного запуска.

### P3 — 2–3 месяца

1. Наладить регулярный контент-план вокруг календаря гонок: превью, расписание, результаты, разбор и обновление сезонных страниц.
2. Получать тематические ссылки через партнёрства с автоспортивными сообществами, подкастами, авторами и профильными медиа.
3. Еженедельно разбирать запросы с высокими показами и низким CTR; улучшать заголовок и сниппет без кликбейта.
4. Ежемесячно проверять:
   - покрытие индекса;
   - дубли title/description;
   - canonical и редиректы;
   - ошибки структурированных данных;
   - битые внутренние ссылки и изображения;
   - страницы без органических показов за 60–90 дней.
5. Обновлять или объединять слабые материалы только по данным; не создавать массовые страницы без самостоятельной пользы.

## KPI на 90 дней

- Не менее 95% валидных canonical URL из sitemap проиндексированы или находятся в ожидаемом статусе обхода.
- 0 критических ошибок структурированных данных.
- 0 индексируемых страниц аккаунта, авторизации, API и приватных лиг.
- 0 массовых дублей title, description и canonical.
- Core Web Vitals на 75-м перцентиле: LCP до 2,5 с, INP до 200 мс, CLS до 0,1.
- Рост небрендовых показов и кликов оценивается относительно baseline, снятого после релиза; целевой ориентир на 90 дней — не менее +25% показов при сохранении или росте CTR.

## Еженедельный SEO-ритм

- Понедельник: индексирование, ошибки обхода и Web Vitals.
- После каждого Гран-при: обновление этапа, результатов, таблиц и внутренних ссылок.
- Среда: запросы с высокими показами и низким CTR.
- Пятница: контент на следующий этап и проверка опубликованных материалов.
- Раз в месяц: полный crawl сайта и сверка sitemap с индексируемыми URL.

## Ограничения текущего этапа

- Нет доступа к данным Google Search Console, Яндекс Вебмастера и аналитики, поэтому текущие позиции и органический эффект ещё не измерены.
- Проверки выполнены на локальной production-сборке; после деплоя нужна отдельная production-проверка.
- Верификационные коды поисковых систем не добавлялись без фактических токенов владельца домена.
- Редакционная стратегия, семантическое ядро и внешние ссылки требуют отдельной регулярной работы, а не только технических изменений в коде.
